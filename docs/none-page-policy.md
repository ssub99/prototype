# 논페이지(None-page) 정책

클래스나 학생이 없어서 화면을 쓸 수 없을 때 보여주는 빈 상태 화면을 **논페이지**라 부르고, 두 종류로 정의한다.

| 종류 | 이름 | 문구 | 버튼 | 가이드(바텀시트) | 버튼 이동 |
|---|---|---|---|---|---|
| `class` | **클래스 논페이지** | 등록된 클래스가 없습니다. | 클래스 만들기 | 클래스 생성 시 기능 활용 안내 (피드·출결관리·학습관리·납부관리) | `class-new.html?from=<화면>` |
| `student` | **학생 논페이지** | 등록된 학생이 없습니다. | 학생 등록하기 | 학생등록 시 기능 활용 안내 (학생관리·청구서·일정·라이브) | `student-add.html?from=<화면>` |

- **개선 전(`before/`)에서는 버튼 아래 "…을 왜 …해야 하나요 ?" 텍스트 버튼(가이드)을 제공하지 않는다.** 개선 후만 보여 준다(`NonePage.render`가 `RzData.version`으로 분기).
- 두 논페이지의 가이드(“…을 왜 …해야 하나요 ?”)는 어느 메뉴에서든 같은 내용이 뜬다. 구현은 `common/none-page.js` 한 곳뿐이다.
- 디자인 원본: 클래스 `320:133189` + 가이드 `320:134123/134240/134346/134449`, 학생 `320:138183` + 가이드 `320:138213/138322/138473/138617`.

## 분기 규칙 (게이트)

**논페이지는 기본값이 없다. 화면(퍼널)마다 필요한 것이 다르고, 요청한 화면에만 요청한 `needs` 로 적용한다.**

- 클래스만 있으면 되는 화면(예: 클래스 관리)은 `["class"]` — 클래스 논페이지만 보여주고, 학생은 확인하지 않는다.
- 학생만 있으면 되는 화면은 `["student"]` — 학생 논페이지만.
- 클래스와 학생이 모두 필요한 기능에서만 `["class","student"]` 로 둘 다 요구한다.
- `needs` 를 넘기지 않으면 아무것도 확인하지 않는다(논페이지 없음). 알아서 둘 다 검사하지 않는다.

`needs` 에 둘 다 있을 때의 동작:
1. 필요한 것 중 비어 있는 게 있으면 **우선순위 클래스 → 학생** 순으로 **가장 먼저 부족한 하나**의 논페이지만 보여준다.
   - 클래스도 학생도 없음 → **클래스 논페이지**
   - 클래스는 있고 학생이 없음 → **학생 논페이지**
   - 둘 다 있음 → 실제 화면
2. 논페이지의 버튼/가이드 마지막 버튼으로 만든 뒤에는 **원래 화면(`from`)으로 돌아오고**, 그 화면이 다시 분기해 다음 논페이지(또는 실제 화면)를 보여준다.
3. 논페이지는 화면의 **본문 영역**을 대체한다. 헤더·상태바는 유지하고, 목록용 요소(검색, ⋮ 메뉴, 푸터 버튼 등)는 숨긴다. 헤더 모양은 해당 화면의 논페이지 디자인을 따른다.

## 코드 사용법

```js
// 화면 진입 시 — needs 는 필수, 그 화면이 요구하는 것만 적는다
const gated = NonePage.gate({ needs: ["class", "student"], from: "attendance" });
if (gated) { /* 본문 자리에 gated 를 넣는다 */ } else { /* 실제 화면 */ }

NonePage.missing({ needs: [...] });      // "class" | "student" | null — 요소 없이 판정만
NonePage.gate({ needs: ["student"], have: { student: false } });  // 범위 한정 판정(예: 이 클래스에 학생 없음)
```

- `needs` 의 순서와 상관없이 우선순위는 항상 클래스 → 학생. `needs` 는 생략할 수 없다(생략 = 검사 없음).
- `have` 로 판정값을 덮어쓸 수 있다. 전체 기준이 아니라 “이 클래스에 학생이 없을 때”처럼 범위가 정해진 경우에 쓴다.
- 새 화면에 적용할 때는 `from` 에 그 화면의 파일명(확장자 제외)을 넘기고, 돌아올 화면이 `class-new.html`/`student-add.html` 의 `from` 매핑에 있는지 확인한다.

## 적용 현황

| 화면 | needs | 비고 |
|---|---|---|
| 클래스 관리 (`class-manage`) | `["class"]` | 클래스 논페이지만. 학생은 확인하지 않음. 논페이지일 때 검색 영역은 제거 |
| 학생/보호자 관리 (`student-manage`) | `["class","student"]` | 클래스 없음 → 클래스 논페이지, 클래스만 있음 → 학생 논페이지 (요청에 따라 둘 다 요구) |
| 학원 출석 관리 (`attendance`) | `["class","student"]` | 클래스 없음 → 클래스 논페이지, 클래스만 있음 → 학생 논페이지 (같은 화면에서 순서대로) |
| 전체 피드 (`feed`) | `["class"]` | 본문만 클래스 논페이지로 대체. 작성된 피드가 없으면 검색 영역은 숨김. 개선 전/후 유형은 NonePage가 버전별로 그림 |
| 피드 글쓰기 (`feed-write`) | `["class"]` | 클래스 논페이지만. 개선 전/후 유형은 NonePage가 버전별로 그림(개선 전은 텍스트 버튼 없음) |
| 학생 명단 (`student-list`) | 직접 `render({kind:"student"})` | 클래스별(범위 한정) 학생 없음 상태만 디자인됨 |
| 학생 등록 (`student-add`) | 적용 안 함 | 실제 폼을 항상 노출(요청에 따름) |
| 홈 My 클래스 / 학원 메인 클래스 목록 | 적용 안 함 | 기존 별도 처리 유지(요청에 따름) |

새 화면에 분기가 필요하면 **화면과 `needs`** 를 요청한다. 요청이 없는 화면에는 적용하지 않는다.

- **예외 — 청구서 생성(`invoice-create`)**: 이 화면 전용 논페이지는 개선 전에도 버튼 아래 "…왜 …해야 하나요 ?" 텍스트 버튼(가이드)을 둔다.
